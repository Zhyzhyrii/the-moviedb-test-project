# TMDB API Test Framework Review

## Что работает хорошо

- **Конфигурация и управление зависимостями.** Параметры аккаунта и токена вынесены в `application.properties` и могут прокидываться через переменные окружения, что упрощает запуск в разных окружениях без правки кода.【F:api-tests/src/main/resources/application.properties†L1-L2】
- **Базовый контроллер и переиспользуемый `RequestSpecification`.** Все контроллеры наследуют общую инициализацию RestAssured: единая базовая точка с авторизацией, типом контента, логированием и кастомным Allure-фильтром, который маскирует чувствительные данные в отчётах.【F:api-tests/src/main/java/org/themoviedb/controllers/BaseController.java†L12-L40】【F:api-tests/src/main/resources/tpl/http-request-masked.ftl†L1-L43】
- **Слои `controller → facade → steps → asserts`.** Слои разнесены и каждый отвечает за свою задачу: контроллеры общаются с API, фасады собирают типовые payload'ы, шаги описывают бизнес-действия в Allure, ассерты инкапсулируют проверки. Такой подход улучшает читаемость и переиспользование шагов.【F:api-tests/src/main/java/org/themoviedb/steps/MoviesSteps.java†L1-L46】【F:api-tests/src/main/java/org/themoviedb/facades/MoviesControllerFacade.java†L1-L26】【F:api-tests/src/main/java/org/themoviedb/assertions/MoviesAsserts.java†L1-L34】
- **Параллельный запуск.** TestNG suite настроен на параллельное выполнение тестов классами, а шаги/ассерты объявлены как `@Scope("prototype")`, что снижает риски гонок из‑за разделяемого состояния при параллельных прогонах.【F:api-tests/src/test/resources/testng.xml†L1-L9】【F:api-tests/src/main/java/org/themoviedb/steps/MoviesSteps.java†L16-L20】
- **Утилиты ожиданий и генерации данных.** Использование Awaitility для опроса рейтингов и генератор диапазона оценок упрощают реализацию тестов, где результат не появляется мгновенно, и дают единый источник случайных данных.【F:api-tests/src/main/java/org/themoviedb/utils/WaitUtil.java†L5-L22】【F:api-tests/src/main/java/org/themoviedb/utils/DataGeneratorUtil.java†L1-L23】

## Что можно улучшить

- **Жёстко закодированная базовая URI и коды ответов.** Адрес API и ожидаемые коды/сообщения успеха в контроллерах и ассертах прописаны литералами. Это усложняет поддержку при смене окружения или локализации и приводит к дублированию строк вроде `"Success."`.【F:api-tests/src/main/java/org/themoviedb/controllers/BaseController.java†L33-L39】【F:api-tests/src/main/java/org/themoviedb/assertions/MoviesAsserts.java†L21-L29】【F:api-tests/src/main/java/org/themoviedb/assertions/AccountAsserts.java†L30-L44】
- **Фасады создают шаблоны запросов вручную.** Например, `UpdateWatchListRequestTemplate` инстанцируется прямо в фасаде, а не внедряется как Spring-бин, что затрудняет подмену/конфигурацию в тестах и увеличивает связанность.【F:api-tests/src/main/java/org/themoviedb/facades/AccountControllerFacade.java†L12-L36】
- **Ограниченная валидация ответов.** Проверки в ассертах часто сводятся к значениям нескольких полей, не анализируют схему ответа, заголовки, метаданные страниц. При добавлении новых полей ошибки могут остаться незамеченными.【F:api-tests/src/main/java/org/themoviedb/assertions/AccountAsserts.java†L30-L69】
- **Нехватка негативных и контрактных тестов.** Набор Happy Path сценариев покрывает только позитивные кейсы; отсутствуют проверки на ошибки валидации, невалидные токены, пустые списки, пагинацию и т. д.【F:api-tests/src/test/java/org/themoviedb/movies/AddRatingToMovieHappyPathTests.java†L1-L45】
- **Дублирование логики ожиданий.** Методы ожидания рейтинга в `AccountControllerFacade` повторяют почти одинаковую логику фильтрации; вместо передачи `Predicate` можно вынести критерии в enum/стратегии или параметризовать метод, чтобы упростить поддержку.【F:api-tests/src/main/java/org/themoviedb/facades/AccountControllerFacade.java†L45-L73】
- **Отсутствие тестового профиля Spring.** Все тесты поднимают полноценный контекст, но нет отдельного `application-test` с заглушками (например, для токена), что делает запуск локально/в CI более хрупким.【F:api-tests/src/test/java/org/themoviedb/BaseTest.java†L1-L8】

## Что добавить

1. **Гибкие конфиги.** Вынести базовый URL и коды/сообщения успеха в `ApiConfig` или отдельные properties, добавить поддержку нескольких окружений через Spring profiles и `application-*.properties`. Это позволит переключаться между dev/stage/prod без перекомпиляции.【F:api-tests/src/main/java/org/themoviedb/configs/ApiConfig.java†L1-L14】【F:api-tests/src/main/java/org/themoviedb/controllers/BaseController.java†L33-L39】
2. **Централизованные проверки и JSON схемы.** Создать библиотеку стандартных assert'ов/JSON-схем для типовых TMDB ответов и подключить в ассертах для жёсткого контроля структуры. Это уменьшит дублирование строк и сделает проверки более точными.【F:api-tests/src/main/java/org/themoviedb/assertions/MoviesAsserts.java†L20-L33】
3. **DataProviders и параметризацию тестов.** Использовать TestNG DataProvider'ы, чтобы прогонять один тест с разными наборами данных (например, разными рейтингами, комбинациями фильмов). Это повысит покрытие без копирования тестов.【F:api-tests/src/test/java/org/themoviedb/movies/AddRatingToMovieHappyPathTests.java†L27-L45】
4. **Библиотеку билдера моделей.** Завести фабрики/билдеры DTO (вместо ручного маппера `RatedMovieDtoMapper`) и переиспользуемые шаблоны запросов как Spring-компоненты. Это упростит конфигурацию payload'ов и тестовых данных.【F:api-tests/src/main/java/org/themoviedb/mappers/RatedMovieDtoMapper.java†L1-L16】【F:api-tests/src/main/java/org/themoviedb/data/requests/UpdateWatchListRequestTemplate.java†L1-L22】
5. **Набор негативных тестов и проверок авторизации.** Добавить сценарии с истёкшим/невалидным токеном, ошибками авторизации, попытками удалить несуществующие элементы. Это поможет выявлять регрессии в обработке ошибок API.【F:api-tests/src/test/java/org/themoviedb/watchlist/*】【F:api-tests/src/test/java/org/themoviedb/movies/*】
6. **Контроль качества тестовых данных.** Ввести precondition сервис/фикстуры, которые гарантируют, что тестовые фильмы/списки существуют и находятся в ожидаемом состоянии перед тестом, чтобы снизить флаки. Сейчас подготовка данных разбросана по тестам и шагам.【F:api-tests/src/main/java/org/themoviedb/steps/AccountSteps.java†L29-L71】
7. **Статическая аналитика и форматирование.** Настроить Checkstyle/Spotless или аналог для единых правил форматирования тестов, а также линтеры для обнаружения copy-paste и пустых TODO (например, `//todo to template`).【F:api-tests/src/main/java/org/themoviedb/assertions/MoviesAsserts.java†L24-L26】
